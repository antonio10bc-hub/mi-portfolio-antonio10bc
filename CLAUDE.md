# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start dev server (http://localhost:3000)
- `npm run build` — production build
- `npm run start` — serve production build
- `npm run lint` — run ESLint (flat config in `eslint.config.mjs`, extends `eslint-config-next` core-web-vitals + typescript)

There is no test suite configured in this repo.

## Architecture

Personal portfolio site (Antonio Asis Bastos de Cordoba), built with Next.js 16 App Router, React 19, TypeScript, and Tailwind CSS 3. Three static routes, each prerendered in English and Spanish, no API routes, no data fetching — all content is hardcoded.

**Languages.** The routes live under `app/[lang]/` (`en`, `es`, both static via `generateStaticParams`, `dynamicParams = false`); the root layout is `app/[lang]/layout.tsx`. `proxy.ts` (Next 16's middleware) rewrites **every public path** (everything except `_next`, `_vercel`, `ingest` and files with an extension) to `/en/...` or `/es/...`, so the visible URL never changes and there is no flash. The language is, in order: the visitor's choice (cookie `lang`, set by the `EN / ES` switch in the footer, `components/LangSwitch.tsx`, which reloads), then Spanish if any `Accept-Language` entry is Spanish or Vercel's `x-vercel-ip-country` is `ES`, then English. Paths that already start with `/en` or `/es` pass through. All interface copy is in `lib/i18n.ts` (`dictFor(lang)` on the server, `DICTS[lang]` in the client gallery); project taglines have a `taglineEs` and photos an `altEs`. Photo titles are artwork names and are not translated. Add new copy to both dictionaries.

**404.** Because every path is rewritten, an unknown URL lands on `/en/<path>` or `/es/<path>`, which `app/[lang]/[...rest]/page.tsx` (dynamic, `dynamicParams = true`) turns into `notFound()`: `app/[lang]/not-found.tsx` renders `components/NotFoundView.tsx` in the right language with a real 404 status. It is a client component only to read `lang` with `useParams` (not-found gets no `params`), and it resets `document.title` because Next applies the layout's title on hydration. The specimen is `public/images/dither/tree-lost.png`: the tree dithered like `tree.png` but lighter, with bands shifted or missing.

**Search and sharing.** `lib/site.ts` holds the public URL (`https://antonio10bc.com`, the production domain on Vercel) and the person's profiles. `lib/seo.ts` builds each page's metadata (`pageMetadata`): title (the layout's template adds `| Antonio Asis`), description, canonical (both languages share one URL, so there is one canonical and no hreflang) and the full `openGraph` / `twitter` blocks, because Next replaces those objects instead of merging them. The share images are `public/og/og-en.png` and `og-es.png` (1200x630: the round halftone canopy of the app icon at 1:1 inside viewfinder brackets, "antonio." and the tagline), rendered with Playwright from HTML with the site's own Archivo and JetBrains Mono. `app/robots.ts` and `app/sitemap.ts` sit at the app root (they need no layout); robots disallows the internal `/en/` and `/es/` paths and `/ingest/`. `components/JsonLd.tsx` prints schema.org data: a `Person` and `WebSite` on the home, an `ItemList` of `VideoGame` on the games page. The games description is built from `PROJECTS` so it stays true when a game is added.

- `app/[lang]/page.tsx` — home, the archive index: the halftone tree as the central specimen with the name, its leader line and the two section panels laid over it. **It must fit in the viewport with no scrolling, footer included**: the root is `min-h-screen-safe` (never a fixed height with `overflow-hidden`, see Mobile). On `md+` the stage is a 12-column grid with rows `auto / minmax(0,1fr) / auto`; it must not be three equal `1fr` rows, because the tallest row then sets the height of all three and the page overflows. Below `md` it is a column with an exact screen height (`.h-screen-safe-mobile`, 100vh then 100svh, written as plain CSS with its own media query because a Tailwind `max-md:` variant would copy only the 100vh rule, and 100vh in Safari is taller than what is visible). In it the tree starts from its natural height (width x 812/1148, image centred with `object-contain`) and **splits the spare height half and half with an empty spacer under the panels**: the tree gets the same air above and below, and the panels sit lower without reaching the footer. Two earlier versions were rejected: tree as plain `flex-1` (it swallowed all the spare height, huge white gaps) and capped at 34svh (no air, panels too high). On short screens the tree shrinks first. Safe-area inset is added to the bottom padding. Check mobile at real Safari visible heights (390x664, 375x553, 430x740), not only full screen sizes. The second panel says "games." and links to `/projects`. The photography panel is solid `panel` (it was `panel/85` and the tree's dots showed through its text) and inverts to ink on hover. On `lg` the tree's area starts at column 4, not 3: with the wider `.page` container the tree is height-bound and grew enough at 1366x768 to run under the end of the tagline. Type sizes are `clamp()` with a `vh` term (`min(13vw,15vh)`) so short laptop screens fit too. Verified at 1920x1080, 1440x900, 1366x768, 1280x720, 1024x768, 768x1024, 430x932, 430x740, 390x844, 390x664, 375x667, 375x553 and 320x568. If you add anything here, re-check that it still fits instead of assuming it does. The counts on the panels come from `lib/photos.ts` and `lib/projects.ts`.
- `app/[lang]/projects/page.tsx`: the games (the page title is "games.", the route stays `/projects`), one grid of project files. On `md+` the header's left column carries a real **contents** index (`G-01 Coinfliip ... #01`), each row an anchor to its card (`id="g-01"`). The grid ends with a `NextFile` panel to photography: with an odd number of games it fills the empty last cell, with an even number it spans both columns. Everything lives in the `PROJECTS: Project[]` array in `lib/projects.ts`; add a game by appending there (with a `screenshot` and a `tint`), not by writing JSX. The web projects were removed on purpose: this page is games only.
- `app/[lang]/photography/page.tsx` — server component holding the page shell. **Every photo carries the paper viewfinder brackets** (four corners, like a camera focusing), with a hard 1px ink shadow so they stay visible over pale skies; the `FR-xx` tag sits beside the top-left corner, aligned with its arm, never on top of it; on `md+` the header's left column has a small viewer spec sheet (frames, ← → to browse, Esc to close) and the page ends with a full-width `NextFile` panel to the games; the featured first photo is `aspect-[16/10]` only below `lg`: in three columns it is `aspect-auto` and takes the row height set by the 4:5 photo next to it (with a fixed 16:10 it ended about 12px lower than its neighbour); the interactive gallery + lightbox is isolated in `components/PhotoGallery.tsx` (the only `"use client"` page-level code). **17 photos is not arbitrary**: the first is featured across 2 of the 3 columns, so 17 photos fill exactly 18 cells, i.e. 6 complete rows with no orphan slot. Adding or removing one leaves a gap unless you add or remove three. The photo list is `lib/photos.ts` — add a photo by dropping the file in `public/images/` and appending an entry there (the page reads the same array to show the frame count).

Content lives in `lib/`, not in the page components, so server pages and the client gallery can share it.

### Art direction

The site follows the **"Specimen File"** art direction in `docs/art-direction/ART_DIRECTION.md` (the prompt plus its translation to this site; the reference poster is next to it). Read it before any visual change. In short: a lab specimen sheet printed on paper. Strictly monochrome interface (white paper, grey panels, ink, graphite), condensed lowercase headlines ending in a full stop, monospace code and data text, halftone specimens, viewfinder brackets, barcodes and data bars. **Colour only ever comes from content** (the photos and the game screenshots, always shown in full colour). No accent colour, no border radius, no soft shadows, no blur, no gradients, no glass.

Coinfliip, Magic Poker and Tank-less were retaken on 2026-10-23 after big updates; when a game changes, retake its screenshot **and** rewrite both taglines from what the game does now (its README, rules text and the running build), not from memory. ### Halftone specimens

`public/images/dither/tree.png` ("Solitude", photo 9, the home; trimmed to its dots, 1148x812, so no transparent margin adds white space around it) and `peak.png` ("Snow Peak", photo 13, the photography header) are the site's own photos printed as halftone: cropped, greyscale, levels pushed until the background goes white, edges dissolved with a radial gradient composited with `lighten`, reduced to a quarter, `-ordered-dither h4x4a`, scaled back up 400% with `-filter point`, and white made transparent. **Render them with `unoptimized`**: `next/image` resamples with smoothing and would blur the dots.

**The home tree is alive** (`components/TreeSpecimen.tsx`, client). It re-dithers the tree every frame on a 287x203 canvas (one pixel per dot, scaled with `image-rendering: pixelated`) from `public/images/dither/tree-src.png`: the same crop, levels and fade as `tree.png`, in greyscale, before dithering. The dither is ImageMagick's `h4x4a` reproduced exactly (matrix `4 2 7 5 / 3 1 8 6 / 7 5 4 2 / 8 6 3 1`, black when `grey * 9 < threshold`, phase offset `(22, 21)` from the trim), so the still frame matches `tree.png` dot for dot and the handover is invisible; if you regenerate one, regenerate both. Three layers: **growth** (first home visit per session, `sessionStorage.treeIntro`: the tree sprouts from the trunk base, `ROOT_X/ROOT_Y`. Each cell has a bloom time, its distance to the root, squashed horizontally and warped by soft sine noise so the front has an organic edge; as the front passes, the cell's tone is faded in from white to its own grey and re-dithered, so the dots appear from light greys to dark like ink blooming. Meanwhile 190 sap sparks climb the trunk on cubic Bézier curves, each timed to reach its canopy cell exactly when the front does, with a five dot flash on arrival. 4 s, easeInOutSine; the front span covers the farthest cell plus the edge width so nothing snaps at the end), **wind** (row and column sine terms precomputed per frame, weighted to the canopy and fading to zero at the trunk and ground, easing in from the first frame, with gusts every 8 to 13 s) and **falling leaves** (single dots that leave dark canopy cells, sway, land, blink out; they start after the growth). A scanner that swept the specimen with a readout, and an earlier print-in where dots flew in on straight lines, were both tried and rejected: too technical and too mechanical. `tree.png` stays in the HTML as the pre-hydration frame and the fallback: an inline script in the home marks `<html data-tree-intro>` before first paint when the growth will play, CSS hides `.tree-png` meanwhile, and a 3 s CSS fallback shows it if JavaScript never takes over. Reduced motion: no canvas at all, just `tree.png`. The loop runs at 30 fps and stops when the tree is off screen or the tab is hidden; measured at about 3% CPU, 15% with 4x CPU throttling. Keep the amplitudes low: stronger wind turns the canopy into noise.

### Layering

`app/[lang]/layout.tsx` renders only the page content (`z-10`). There is no film-grain overlay, no custom cursor and no top row of three headlines — all removed on purpose; don't reintroduce them.

`<html>` carries `suppressHydrationWarning`: the home's boot script sets `data-tree-intro` on it before hydration, which otherwise logs a hydration mismatch on every first visit.

The lightbox in `PhotoGallery` renders through `createPortal` to `document.body` at `z-50`, outside `PageTransition`'s wrapper. It also locks `document.body.style.overflow` while open and restores the previous value on close.

### Copy

- **Never use a dash as punctuation anywhere on the site**: no em dash, no en dash, no double hyphen. Use a comma, a colon or a full stop instead. This applies to taglines, intros, metadata titles and any new copy. (`--font-inter` and friends are CSS variable names, not copy, and stay as they are.)
- Site copy is English by default with a Spanish version in `lib/i18n.ts` (and `taglineEs` / `altEs` in `lib/`); repo comments are in Spanish. The no-dash rule applies to both languages.
- Project taglines and stack tags describe what each site actually is; they were written after visiting the live URLs. Keep them factual rather than decorative.

### Mobile (read before adding blur or hover)

The site looked fine in a narrow desktop window and broke on a real phone. The causes were rendering cost and touch semantics, not layout, so a narrow desktop window will not catch a regression here. Rules:

- **No `backdrop-filter`.** It was the most expensive thing on the page; the art direction no longer uses glass, and the lightbox overlay is solid `ink/95`.
- **No `filter: blur()` on large elements.** Safari on iOS rasterises it in tiles, which showed up on a real iPhone as a hard horizontal seam across an old background.
- **Section titles use `clamp()`, never a bare `text-5xl md:text-7xl`.** "Photography" at the old fixed 48px was 346px wide inside a 310px card and spilled out of its card on a phone. Measure the *text* with a Range, not the `h1`'s `scrollWidth`: the heading is a block, so its scrollWidth reports the container width and hides the overflow.
- **The staggered `.reveal` entry is off below `md`.** On a phone it read as the cards loading in one by one.
- **No `mix-blend-mode` anywhere.** It renders unpredictably in Safari on iOS, and having mobile and desktop compute colour differently is exactly how the two diverge. Colour comes from plain opacity, which every browser paints identically.
- **`hoverOnlyWhenSupported` is on** in `tailwind.config.ts`, so `hover:`/`group-hover:` compile inside `@media (hover: hover) and (pointer: fine)`. Without it a tap left cards stuck in their hover state. Never make something reachable *only* through hover: on a phone those rules never fire, which is why nothing on the cards depends on hover to be seen.
- **Viewport height goes through `.min-h-screen-safe`**, never a bare `h-screen`/`100svh`. It is `100vh` with a `100svh` override inside `@supports`. The override must stay in `@supports`: as two plain declarations the build's minifier drops the `100vh` fallback, which strands browsers without `svh` (iOS < 15.4) with no height at all.
- **Never pair a fixed viewport height with `overflow-hidden` on a page root.** If anything fails to fit on a real device the content is clipped with no way to scroll to it. The home uses `min-h-screen-safe` and no clipping, so a bad fit degrades into a scroll.

- **Never put `overflow-x: hidden` on `html`/`body` as an overflow safety net.** It breaks `position: fixed` descendants in Safari on iOS (the fixed background stops covering the page and leaves a seam), and it silently masks real overflow so the measurement below becomes meaningless. Fix overflow where it originates instead.

Verified with CDP under iPhone emulation (touch events, DPR 3, iOS user agent): no horizontal overflow on any route, the home fits with its footer from 1920x1080 down to 320x568, and the lightbox opens, locks the background and closes from real `touchStart`/`touchEnd`.

### Styling

- Theme colours in `tailwind.config.ts`: `paper` (page), `panel` (grey panels), `ink` (text, rules, dots), `graphite` (dark action panel), `mute` (secondary text, only on `paper`: 5.5:1 there, under 4.5:1 on `panel`). Use the tokens, never hardcoded hex.
- Type classes in `app/globals.css`: `.display` (Archivo at `wdth` 62, weight 800, lowercase, tight; the width goes through `font-variation-settings`, not `font-stretch`), `.code` (bold uppercase mono identifiers), `.label` (mono microtype) and `.datatext` (small justified mono; the uneven justification spacing is intended, it is in the reference).
- **Tailwind only generates opacity modifiers from its scale** (…, 10, 15, 20, 25, …, 90, 95, 100). `bg-ink/92` produces no CSS rule at all and fails silently — this has bitten this repo twice.
- Entry animations use the `.reveal` class plus an inline `animationDelay` for stagger. Keep `.reveal` on a wrapper, never on an element that also animates `transform` on hover — the fill-mode would pin the transform and kill the hover.
- `globals.css` neutralises all animation/transition durations under `prefers-reduced-motion`.
- Fonts: `Archivo` (with the `wdth` axis) + `JetBrains_Mono` via `next/font/google`, exposed as `--font-archivo` / `--font-jetbrains-mono` and mapped to `font-sans` / `font-mono`. Two families, never more.

### Images

Source photos in `public/images/` are capped at 2560px wide, quality 80. Only the files listed in `lib/photos.ts` live there (two unused ones were removed); delete a photo's file when you remove its entry. Keep new uploads in that range — the originals were 6000px / ~3.5 MB each and bloated the repo.

**`next/image` `quality` is a no-op here.** Next 16 only honors quality values listed in `images.qualities` (default `[75]`); anything else silently falls back to 75. To serve a different quality, add `images: { qualities: [...] }` to `next.config.ts` first.

`next.config.ts` pins `turbopack.root` to this directory — there is a stray `package-lock.json` in the user's home folder that Next would otherwise infer as the workspace root.

### App icon

The mark is **a round close-up of the home tree's canopy**: a 640px square of foliage from "Solitude" (photo 9, `+930+200`, so the trunk junction shows at the bottom), greyscale, levels 6% to 72%, cut into a circle by a radial gradient composited with `lighten` (`-level 72%,88%`, so the edge dissolves into dots), printed as halftone in `ink` on white paper. It has to read round: two earlier marks were rejected, the canopy crowning an "A", and the whole tree isolated, whose wide flat crown on a trunk looked like a mushroom cloud. **Each size is dithered natively** (`h4x4a`) at a cell count that divides it evenly, so every dot is a whole number of pixels: `icon-512.png` and `icon.png` (256) at 128 cells, `icon-192.png` at 96, `apple-icon.png` (180) at 90, and `icon-maskable-512.png` at 100 cells drawn into 400px so it stays inside the 80% safe circle. `app/favicon.ico` (16 + 32) is dithered directly at 1 cell per pixel with `o2x2`. `app/manifest.ts` and the `appleWebApp` / `viewport.themeColor` exports in `app/layout.tsx` make "Add to Home Screen" show it with the short name "Antonio". Regenerate all six files together if the mark changes.
