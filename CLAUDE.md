# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start dev server (http://localhost:3000)
- `npm run build` — production build
- `npm run start` — serve production build
- `npm run lint` — run ESLint (flat config in `eslint.config.mjs`, extends `eslint-config-next` core-web-vitals + typescript)

There is no test suite configured in this repo.

## Architecture

Personal portfolio site (Antonio Asis Bastos de Cordoba), built with Next.js 16 App Router, React 19, TypeScript, and Tailwind CSS 3. Three static routes, each prerendered in English and Spanish, no API routes, no data fetching — all content is hardcoded.

**Languages.** The routes live under `app/[lang]/` (`en`, `es`, both static via `generateStaticParams`, `dynamicParams = false`); the root layout is `app/[lang]/layout.tsx`. `proxy.ts` (Next 16's middleware) rewrites **every public path** (everything except `_next`, `_vercel`, `ingest` and files with an extension) to `/en/...` or `/es/...`, so the visible URL never changes and there is no flash. The language is, in order: the visitor's choice (cookie `lang`, set by the `EN / ES` switch in the footer, `components/LangSwitch.tsx`, which reloads), then Spanish if any `Accept-Language` entry is Spanish or Vercel's `x-vercel-ip-country` is `ES`, then English. Paths that already start with `/en` or `/es` pass through. All interface copy is in `lib/i18n.ts` (`dictFor(lang)` on the server, `DICTS[lang]` in the client gallery); project taglines have a `taglineEs` and photos an `altEs`. Photo titles are artwork names and are not translated. Add new copy to both dictionaries.

**404.** Because every path is rewritten, an unknown URL lands on `/en/<path>` or `/es/<path>`, which `app/[lang]/[...rest]/page.tsx` (dynamic, `dynamicParams = true`) turns into `notFound()`: `app/[lang]/not-found.tsx` renders `components/NotFoundView.tsx` in the right language with a real 404 status. It is a client component only to read `lang` with `useParams` (not-found gets no `params`), and it resets `document.title` because Next applies the layout's title on hydration. It shows the wizard without sparkles and with hand-drawn question marks over his hat: "poof!", the page vanished.

**Search and sharing.** `lib/site.ts` holds the public URL (`https://antonio10bc.com`, the production domain on Vercel) and the person's profiles. `lib/seo.ts` builds each page's metadata (`pageMetadata`): title (the layout's template adds `| Antonio Asis`), description, canonical (both languages share one URL, so there is one canonical and no hreflang) and the full `openGraph` / `twitter` blocks, because Next replaces those objects instead of merging them. The share images are `public/og/og-en.png` and `og-es.png` (1200x630: "hi! i'm" / "¡hola! soy", "antonio" hand-lettered and underlined, the tagline in pencil grey, and the stamp wizard with his two cats pointing his wand at the name, with a few crosses), rendered with Playwright from HTML with Shantell Sans; the wizard is copied from the live home's SVG so it is the same drawing. Regenerate them with the icons (see App icon). `app/robots.ts` and `app/sitemap.ts` sit at the app root (they need no layout); robots disallows the internal `/en/` and `/es/` paths and `/ingest/`. `components/JsonLd.tsx` prints schema.org data: a `Person` and `WebSite` on the home, an `ItemList` of `VideoGame` on the games page. The games description is built from `PROJECTS` so it stays true when a game is added.

- `app/[lang]/page.tsx` — home, **a scene** with the composition of a children's play page (the user liked a "woset" Play page and asked for this layout with only one thing in the middle): `TopBar` on top; in the middle the hand-written uppercase sentence "antonio takes photos / and makes little games" in two staggered lines (`SpellCaption`, the page's `h1`), and under it **one floating work** (`FloatingWork`) that cycles through photos and games, held up by the wizard and his cats on the right (`WizardButton`); at the bottom, three blocks: "Antonio Asis" in calm lettering (no informality, no bounce) with a one-line bio and the Instagram, the hand-drawn pills (`SpellPills`: photography, games, cast a spell, say hi) and the seven spell marks with the line slider (`SpellMarks`). The home has no footer; the language is in the top bar. An earlier version put several photos and screenshots in a pile in the middle: the user asked for a single one, bigger. **It must fit in the viewport with no scrolling**: the root is `min-h-screen-safe` (never a fixed height with `overflow-hidden`, see Mobile); top bar and bottom row are `shrink-0` and the scene is the only `flex-1`. Inside the scene the work and the wizard are absolutely placed by percentages of the scene (desktop: work from 14% left, 40% wide, full height; wizard 82% high at 6% from the right; mobile: work on top, 82% wide and 64% high, wizard 40% high bottom right, which is why the work's caption is left-aligned on mobile). Safe-area inset is added to the bottom padding. Verified at 1920x1080, 1440x900, 1366x768, 1280x720, 1024x768, 768x1024, 430x932, 430x740, 390x844, 390x664, 375x667, 375x553 and 320x568, in English and Spanish. If you add anything here, re-check that it still fits instead of assuming it does.

The web projects were removed on purpose: this page is games only.

The featured first photo is `aspect-[16/10]` only below `lg`: in three columns it is `aspect-auto` and `flex-1`, so it fills the row height minus its caption, the same as the 4:5 photo beside it, and the two line up. Content lives in `lib/`, not in the page components, so server pages and the client gallery can share it.

### Art direction

The site follows the **"Cuaderno de tinta"** (ink notebook) art direction in `docs/art-direction/ART_DIRECTION.md` (the prompt plus its translation to this site). The reference was someone else's drawing of a naive ink wizard; it is described there in words and deliberately not kept in the repo. Read it before any visual change. In short: the sketchbook of a wizard who makes photos and games, drawn in thick black marker on white paper. Strictly monochrome interface (paper, ink, pencil grey), one hand-lettered typeface (Shantell Sans), a closed vocabulary of hand-drawn marks (the robe's "+" cross, hand-drawn frames, circles, underlines and arrows, ink blobs) and lines that draw themselves. **Colour only ever comes from content** (the photos and the game screenshots, always in full colour). No accent colour, no shadows, no blur, no gradients, no glass. The previous "Specimen File" identity (halftone, brackets, barcodes) is in the git history.

Page chrome is factored out — do not re-inline it:

- `ProjectCard`: one notebook entry per game: its number in an ink blob, the **real screenshot** of the game (`public/images/projects/*.webp`, 1280x800, quality 80) on its `tint`, stuck on tilted (alternating by position) inside a hand-drawn frame that draws on scroll and straightens on hover, the name hand-lettered, the tagline in pencil and "play", circled on hover. **The screenshots are served `unoptimized`** (they are already 1280px WebP) and the first two load with `priority`: through the image optimiser they were generated on the first visit and took a moment to appear. The screenshots were taken locally from each game's own repo (`antonio10bc-hub/neobrutalist-flip` is Coinfliip, `MagicPoker`, `asciiforest`, `chaoticgolfweb`, `tanquesweb` is Tank-less) with Playwright at 1024x640, DPR 1.25 (ASCII Forest at 1280x800, it needs the wider view), with dev badges, cookie banners and debug buttons hidden. What each one shows: Coinfliip in a game with a heads streak (Firebase stubbed, the streak flames hidden because they cover the UI), Magic Poker and Tank-less on their main menu (Tank-less is WebGL: launch Chromium with `--use-angle=swiftshader --enable-unsafe-swiftshader`, and seed `tankless.profile` with `tutorialDone: true` to skip the tutorial), ASCII Forest after its debug `UNLOCK ALL`, Chaotic Golf on its menu. Coinfliip, Magic Poker and Tank-less were retaken on 2026-10-23 after big updates; when a game changes, retake its screenshot **and** rewrite both taglines from what the game does now (its README, rules text and the running build), not from memory. Retake them the same way rather than drawing illustrations: the card must look like the game. **Each card also plays a short gameplay video** (`video` in `lib/projects.ts`, a path without extension: `public/videos/projects/<name>.webm` in VP9, listed first because Chromium builds without H.264 still play it, and `<name>.mp4` in H.264 for Safari; 960x600, 5 to 7 s, muted loop, no audio track, about 3 MB for all ten files) through `components/GameMedia.tsx`: the screenshot stays as the first frame and fallback, the sources carry their URL in `data-src` and are only set (then `load()`) when the card is on screen (IntersectionObserver), pauses when it leaves, fades in once it is actually playing, and is skipped with reduced motion or Save-Data. The card's own `transform` is never animated; entry animations belong on the wrapper in the page.
- **The ink vocabulary** lives in three files. `lib/ink.ts`: the geometry (deterministic noise from a text seed, Catmull-Rom smoothing, and the shapes that stretch with their box: `roughRect`, `roughEllipse`, `roughUnderline`). `components/InkBox.tsx` (client): `InkFrame`, `ScribbleCircle` and `Scribble`, which **measure their own box with a ResizeObserver and draw in real pixels**; until measured (the server HTML) the SVG is empty. All decorative and `aria-hidden`, in `currentColor`; never `Math.random()`, so server and client HTML match.
- `NextFile`: the close of `/photography`: "next up", "games" hand-lettered and a big curly arrow, inside a hand-drawn frame that draws on scroll. No images of the other section. Tracked as `next_file_clicked`, like the link in the games' end.

The 20px on mobile is what the frames need: outset + corner overshoot (capped at 9px in `roughRect`) + tilt, which overflowed the old 16px.
- `PageTransition` — wraps `{children}` in `app/[lang]/layout.tsx` and cross-fades routes with a CSS animation (`animate-fade-in`) on a `div` keyed by `usePathname()`. ### The wizard

`Wizard` in `components/Ink.tsx` is an original drawing in the style of the reference (not a copy of it), the one the user picked out of ten proposals: **"the stamp"**, a solid ink silhouette (cone hat with a bent tip, robe, sleeve, feet) with the robe's "+" crosses, a few specks and the hat spots in white, a white beard and long nose, a wand; plus **two cats** at his feet that the user asked for, a **spotted** one on the left (white with ink spots, the mirror of the other, looking at him) and a **grey** one on the right (`CAT_GREY`, the only grey in the drawing). Each part has a kind: white fill with outline, outline only, solid ink without outline, solid with outline (`kk`: the outline draws, then the fill fades in via `.ink-fill`), white stroke (the crosses on the black robe), white dot, and grey fill. It is a list of paths in a 240x290 viewBox (`WIZARD`, plus `WIZARD_DOTS` for the eye and hat spots), each with its draw time `t`: on load the strokes draw in that order and the blobs and dots pop, done by `WIZARD_DRAWN` (1.9 s). Then the **sparkles** start: crosses that leave the wand tip at (8, 180) towards the left, spin and fade, in a loop. They are inside the wizard's own SVG, not an HTML layer, so they follow the wand however the drawing is scaled or letterboxed (CSS transform lengths on SVG elements are in viewBox units). The whole drawing sways (`animate-bob`, rotating around the feet). One SVG filter, only here: `feTurbulence` + `feDisplacementMap` that ripples the edges like ink on paper. It only displaces, it does not blur, and it is applied to a small static drawing (the sway is a transform on the whole SVG, so the filter is not re-run per frame). Props: `sparkles` (off on the 404), `animate`, `id` (the filter id, unique per page). The parts flagged `arm` (arm, hand, wand) render inside one `<g class="wizard-arm">` so they can rotate from the shoulder at (112, 142), and the eye carries `wizard-eye`; the poses in `globals.css` use both: `wizard-idle` blinks, `wizard-cast` hops and raises the wand, `wizard-shake` shakes the head. The hop and shake go on a wrapper and the sway on the SVG, so the two transforms never fight. A replacement wizard must keep this structure (wand tip at (8, 180), the arm group, the eye) for the sparkles and the minigame to keep working.

### Spells and the minigame

All the magic happens on the home itself, with no separate screen (an earlier version opened a full-screen overlay and the user did not want a separate menu). `SpellProvider` (`components/SpellProvider.tsx`) wraps the scene and the bottom row and holds the state. Two ways to cast:
- **A free spell**: any of the seven marks at the bottom right makes the wizard cast it at once at the floating work, with no drawing. The page stays fully usable.
- **The minigame**: clicking the wizard or the "cast a spell" pill. The sentence of the scene becomes the **scoreboard** ("antonio": letters drawn right in ink, the current one with a wavy underline, the rest pencil-light) and the game's messages ("now draw: a", the spell's name, the miss message, and at the end "you know my name. abracadabra." with "again" and "close"); you draw the letters of the name on the page itself, over a huge faint guide of the next one, and each casts its spell from the wand to where it was drawn: **a fire, n water, t wind, o earth, n lightning, i ice, o light** (`NAME` in `lib/spellbook.ts`; by position, so the two n and the two o differ). A miss turns the strokes into smoke and the wizard shakes his head; after the last o, a rain of crosses. Esc or the X leave; the page scroll is locked meanwhile. Analytics: `minigame_opened`, `minigame_missed`, `minigame_completed`, `spell_cast`.

Both paint in `SpellLayer`, a transparent full-screen canvas loaded with `next/dynamic` only when first needed, which **retires itself** 4 s after the last free spell when no game is running. In free mode it takes no pointer events at all; in the game only the canvas (while drawing) and the X take them, so "again" and "close" stay clickable when the name is complete. The wand tip comes from the wizard's SVG on the home (`wizardRef`), the free spells aim at the centre of the floating work (`targetRef`), and a free spell asked for before the layer has mounted waits in `pending` and is cast on mount.

- **Recognition** is the $P point-cloud recognizer (Vatavu, Anthony and Wobbrock, 2012) in `lib/spellbook.ts`, with hand-authored templates for a, n, t, o, i in lower and upper case and their common shapes. It ignores stroke order and direction and handles several strokes (the bar of the t, the dot of the i). The letter is read 650 ms after the last stroke ends. It is lenient on purpose: the expected letter wins if it is the best match or within 1.3x of it, and anything scoring over 1.8 is rejected. Those thresholds were measured on synthetic handwriting (stretched, slanted, rotated, jittered, strokes reordered and reversed): 97 to 100% of right letters accepted, wrong letters almost never, 5% of random scribbles. If you add templates, re-measure instead of guessing.
- **Spells** are canvas particle effects in `lib/spells.ts`, all in ink: hand-drawn flames, drops and ripples, spiral gusts and leaves, falling rocks that crack the ground, branching bolts with a dark flash, ice spikes and snowflakes, rays and a burst of the robe's crosses. One requestAnimationFrame loop while spell mode is on. **New effects go through a queue** (`queued`) and join the list on the next frame: the projectile casts its spell from inside its own `update`, which runs while the loop filters the effect list, and `filter` does not see items pushed mid-pass. Pushing straight into the list made every spell but lightning (cast from a `setTimeout`) silently vanish.
- Touch drawing works because the canvas is `touch-none` and uses pointer events with `setPointerCapture` and coalesced events. Verified with real CDP touch events at 390x844.

### Drawn lines

Every stroke has `pathLength="1"` and the class `ink-line` (`stroke-dasharray: 1`, offset 0: fully drawn, which is the resting state). Animating the offset from 1 to 0 draws it. `.ink-draw` draws on load with the delay in `--d` (the wizard, underlines, doodles, the active nav circle); `.ink-hover` stays hidden and draws on `.group` hover or keyboard focus (the circles around links); `.ink-scroll` draws with scroll on `md+`, following the **named `view-timeline` of its `.ink-host`** (the photo button, the card's media, the end panels). Never `animation-timeline: view()` on the stroke itself: an ancestor with `overflow: hidden` becomes the scroll container and `view()` measures against it, so the effect silently never plays. The `ink-draw` keyframes are declared in `globals.css` itself, because Tailwind only emits keyframes for `animate-*` classes in use. Under reduced motion every animation and its delay are zeroed, so everything shows already drawn. Without `animation-timeline` support the frames are simply there.

### Layering

`app/[lang]/layout.tsx` renders only the page content (`z-10`). There is no film-grain overlay, no custom cursor and no top row of three headlines — all removed on purpose; don't reintroduce them.

The lightbox in `PhotoGallery` renders through `createPortal` to `document.body` at `z-50`, outside `PageTransition`'s wrapper. It also locks `document.body.style.overflow` while open and restores the previous value on close.

### Copy

- **Never use a dash as punctuation anywhere on the site**: no em dash, no en dash, no double hyphen. Use a comma, a colon or a full stop instead. This applies to taglines, intros, metadata titles and any new copy. (`--font-inter` and friends are CSS variable names, not copy, and stay as they are.)
- Site copy is English by default with a Spanish version in `lib/i18n.ts` (and `taglineEs` / `altEs` in `lib/`); repo comments are in Spanish. The no-dash rule applies to both languages.
- Project taglines and stack tags describe what each site actually is; they were written after visiting the live URLs. Keep them factual rather than decorative.

### Mobile (read before adding blur or hover)

The site looked fine in a narrow desktop window and broke on a real phone. The causes were rendering cost and touch semantics, not layout, so a narrow desktop window will not catch a regression here. Rules:

- **No `backdrop-filter`.** It was the most expensive thing on the page; the art direction no longer uses glass, and the lightbox overlay is solid `ink/95`.
- **No `filter: blur()` on large elements.** Safari on iOS rasterises it in tiles, which showed up on a real iPhone as a hard horizontal seam across an old background. The wizard's ink filter is a displacement on one small static drawing, not a blur; do not spread SVG filters to frames or photos.
- **Section titles use `clamp()`, never a bare `text-5xl md:text-7xl`.** "Photography" at the old fixed 48px was 346px wide inside a 310px card and spilled out of its card on a phone. Measure the *text* with a Range, not the `h1`'s `scrollWidth`: the heading is a block, so its scrollWidth reports the container width and hides the overflow.
- **The staggered `.reveal` entry is off below `md`.** On a phone it read as the cards loading in one by one.
- **No `mix-blend-mode` anywhere.** It renders unpredictably in Safari on iOS, and having mobile and desktop compute colour differently is exactly how the two diverge. Colour comes from plain opacity, which every browser paints identically.
- **`hoverOnlyWhenSupported` is on** in `tailwind.config.ts`, so `hover:`/`group-hover:` compile inside `@media (hover: hover) and (pointer: fine)`. Without it a tap left cards stuck in their hover state. Never make something reachable *only* through hover: on a phone those rules never fire, which is why nothing on the cards depends on hover to be seen.
- **Viewport height goes through `.min-h-screen-safe`**, never a bare `h-screen`/`100svh`. It is `100vh` with a `100svh` override inside `@supports`. The override must stay in `@supports`: as two plain declarations the build's minifier drops the `100vh` fallback, which strands browsers without `svh` (iOS < 15.4) with no height at all.
- **Never pair a fixed viewport height with `overflow-hidden` on a page root.** If anything fails to fit on a real device the content is clipped with no way to scroll to it. The home uses `min-h-screen-safe` and no clipping, so a bad fit degrades into a scroll.

- **Never put `overflow-x: hidden` on `html`/`body` as an overflow safety net.** It breaks `position: fixed` descendants in Safari on iOS (the fixed background stops covering the page and leaves a seam), and it silently masks real overflow so the measurement below becomes meaningless. Fix overflow where it originates instead.

Verified with CDP under iPhone emulation (touch events, DPR 3, iOS user agent): no horizontal overflow on any route, the home fits with its footer from 1920x1080 down to 320x568, and the lightbox opens, locks the background and closes from real `touchStart`/`touchEnd`.

### Styling

- Theme colours in `tailwind.config.ts`: `paper` (page and lightbox), `ink` (text, strokes, blobs), `mute` (pencil grey for notes and secondary text, 6:1 on paper) and `smudge` (the placeholder behind a loading photo, nothing else). Use the tokens, never hardcoded hex.
- Type classes in `app/globals.css`: `.hand-display` (weight 800, `INFM` 100, `BNCE` 55, lowercase; on `.group` hover or `.wiggle:hover` the bounce flips to -55, so the letters dance), `.hand` (body text), `.note` (small pencil margin notes) and `.label` (short uppercase data). The axes go through `font-variation-settings`; the body sets `INFM` 100 and `BNCE` 15.
- **Tailwind only generates opacity modifiers from its scale** (…, 10, 15, 20, 25, …, 90, 95, 100). `bg-ink/92` produces no CSS rule at all and fails silently — this has bitten this repo twice.
- Entry animations use the `.reveal` class plus an inline `animationDelay` for stagger. Keep `.reveal` on a wrapper, never on an element that also animates `transform` on hover — the fill-mode would pin the transform and kill the hover.
- `globals.css` neutralises all animation/transition durations under `prefers-reduced-motion`.
- Font: `Shantell_Sans` via `next/font/google` with the `INFM` and `BNCE` axes, exposed as `--font-shantell` and mapped to `font-sans`. One family, never more.

### Images

Source photos in `public/images/` are capped at 2560px wide, quality 80. Only the files listed in `lib/photos.ts` live there (two unused ones were removed); delete a photo's file when you remove its entry. Keep new uploads in that range — the originals were 6000px / ~3.5 MB each and bloated the repo.

**`next/image` `quality` is a no-op here.** Next 16 only honors quality values listed in `images.qualities` (default `[75]`); anything else silently falls back to 75. To serve a different quality, add `images: { qualities: [...] }` to `next.config.ts` first.

`next.config.ts` pins `turbopack.root` to this directory — there is a stray `package-lock.json` in the user's home folder that Next would otherwise infer as the workspace root.

### App icon

The mark is **the wizard's hat** as it is now: the same cone with the bent tip, solid ink with four white spots and a thick brim, with two "+" crosses, on white, with the wizard's ink filter. `icon-512.png`, `icon-192.png`, `app/icon.png` (256) and `app/apple-icon.png` (180) share one framing; `icon-maskable-512.png` has more margin so the hat stays inside the 80% safe circle. `app/favicon.ico` (16 + 32) is the hat **solid** on a transparent background: at that size an outline does not read. All of them, and the share images, are rendered with Playwright from inline SVG and HTML (a scratch script, not in the repo). The `.ico` is two PNGs packed by hand; **Next only decodes PNGs with an alpha channel inside an `.ico`** ("The PNG is not in RGBA format!" took the whole site down with a 500), and Chrome writes RGB when no pixel is transparent, so the favicon must have a transparent background. `app/manifest.ts` and the `appleWebApp` / `viewport.themeColor` exports in `app/layout.tsx` make "Add to Home Screen" show it with the short name "Antonio". Regenerate all of them together if the mark changes.
